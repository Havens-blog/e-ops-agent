# Journey: 告警自动排查 → 风险中心跟进

一线值班运维接收告警触发的诊断推送，在风险中心按租户/时间/服务名筛选，单条或批量标记「已查看/已处理」，并正确处理并发冲突与批量部分失败。

## Happy Path Steps

1. 告警经 webhook（X-Opsagent-Webhook-Key）到达编排层，指纹聚合去重后触发自动排查，诊断结果落库。
2. 值班运维进入 `/opsagent/risk-center`，默认加载本租户条目，统计卡展示待处理/今日新增/高危三计数。
3. 按服务名/状态/severity/时间窗筛选，列表仅显示匹配本租户、本时间窗、本服务的条目（跨租户不可见）。
4. 打开一条「待查看」条目跳转诊断详情（携带 riskEntryId），返回时条目状态已自动流转「已查看」。
5. 单条或批量标记「已处理」，成功后列表状态刷新；失败项（冲突/不存在）回显失败清单并提供重试入口。

## Edge Cases

1. 我标记时另一值班已抢先标记为其他状态 → 409 提示「已被其他值班更新」并刷新最新状态，未经确认不覆盖。
2. 批量标记部分成功：任一冲突项落入失败清单（reasonCode=conflict + currentVersion），其余成功项状态一致变更。
3. 同指纹告警在 10 分钟窗口内重复到达 → 仅一次排查，重复告警归并到既有诊断记录，不产生重复条目。
4. 排查并发超上限（默认 5）→ 超出部分入队等待而非丢弃；队列超上限（默认 100）→ 低级别溢出丢弃但保留原文，高危告警不丢弃。
5. LLM 预算耗尽 → 输出纯规则结论（带降级标识），排查与推送不中断。
6. 高危条目（severity P0/P1）仅展示「待人工确认」，不渲染任何确认/执行控件。
7. 标记一个不存在的条目或跨租户条目 → 404，不泄露资源存在性。

## Invariants

- 租户隔离：一切查询/写入带 tenant_id 过滤，跨租户一律 404 不泄露存在性。
- 版本记账：risk_entries.version 每次成功更新 $inc +1；expectedVersion 过滤 findAndModify，冲突不静默覆盖。
- 高危不写：P1 只读，高危条目不暴露确认/执行控件。
- 去重宁多勿漏：Redis SET NX 快闸 fail-open，高危告警不丢弃。

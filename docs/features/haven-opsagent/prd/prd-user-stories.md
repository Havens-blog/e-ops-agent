# User Stories: Haven 运维 Agent

## Story 1: 一线值班运维接收告警并跟进待办

**As a** 一线值班运维
**I want to** 接收告警自动触发的诊断推送，在风险中心按租户/时间/服务名查看、筛选，并单条或批量标记「已查看/已处理」
**So that** 我不用在多个系统间手动切换串联，就能看到每条告警的排查结论和处置预案，并记录自己处理到哪一步。

**Acceptance Criteria:**
- Given 一条告警已到达编排层且指纹聚合去重后触发自动排查
- When 排查完成、诊断结果落库
- Then 风险中心出现该告警对应的诊断条目，含结论 + 分级处置预案 + 数据源引用
- Given 我在风险中心看到多条诊断条目
- When 我按租户 / 时间 / 服务名筛选
- Then 仅显示匹配本租户、本时间窗、本服务的条目（跨租户不可见）
- Given 我打开一条「待查看」条目（列表内展开或进入详情页）
- When 内容展示完成
- Then 该条目状态自动流转为「已查看」，无需额外点击，且不触发任何写操作
- Given 我查看完一条「已查看」条目
- When 我标记「已处理」
- Then 该条目状态流转为「已处理」，且不触发任何写操作
- Given 我勾选多条条目并点击「批量标记已查看 / 已处理」
- When 批量操作执行完成
- Then 全部成功时所有勾选条目状态一致变更；部分失败时仅成功条目变更，页面回显失败清单（含条目与失败原因）并提供「重试失败项」入口
- Given 同一指纹的告警在滚动窗口（默认 10 分钟，可配置）内重复到达
- When 编排层指纹聚合去重生效
- Then 窗口内仅触发一次自动排查，重复告警归并到既有诊断记录，不产生重复条目
- Given 告警自动排查并发超过上限（默认 5）
- When 新告警进入编排层
- Then 超出部分进入等待队列排队而非丢弃；队列长度未超上限（默认 100 条）时排队等待处理
- Given 排查等待队列已满（超过默认 100 条上限）
- When 新告警进入编排层
- Then 溢出的低级别告警排查被丢弃，但保留告警原文与去重结论可查；高危告警不因队列溢出被丢弃
- Given LLM 调用预算耗尽
- When 告警触发自动排查
- Then 降级输出纯规则结论（带降级标识），排查不中断、推送风险中心不中断
- Given 一条诊断条目已落库并推送风险中心
- When 外部通知渠道发送告警提醒
- Then 经已配置的渠道（钉钉 / 飞书 / 企业微信 / 邮件）送达告警摘要与诊断入口链接；推送失败自动重试，仍失败计入推送失败率（SC-2 口径），不影响风险中心条目落库与展示
- Given 我查看一条高危条目（P1，执行通道未上线）
- When 页面渲染该条目（列表或诊断详情）
- Then 页面不渲染任何「确认 / 执行 / 立即处置」类控件，仅展示「待人工确认（执行通道 P3 上线后生效）」标记与预案操作清单
- Given 我正在标记某条目，且另一名值班已先将其标记为其他状态（如「已处理」）
- When 我提交标记
- Then 系统提示「该条目已被其他值班更新为 X」并刷新为服务端最新状态，需我重新确认后方可覆盖提交；未经确认不发生覆盖

## Story 2: 一线值班运维用对话快速定位故障

**As a** 一线值班运维
**I want to** 用自然语言问「某服务最近一小时是不是出错/被刷了」，快速得到只读诊断报告
**So that** 我能用对话而非手工查日志、查资产、查告警来完成一次「告警→定位」，把单次耗时压到 1 分钟内。

**Acceptance Criteria:**
- Given 我以自然语言提问（含服务名 + 时间范围 + 现象）
- When 编排层完成意图识别、调用日志/资产/告警底座并组装报告
- Then 我在 1 分钟内（端到端，含 LLM 解读）收到含根因 + 处置建议 + 数据源引用的只读诊断报告
- Given LLM 不可用（判定：单次调用超时 > 12 秒，或连接失败 / 连续 2 次调用失败；见 PRD Spec Performance Requirements）
- When 我发起对话提问
- Then 系统按三级降级（模板意图匹配 / 预置查询入口 / 明示降级模式）响应，而非静默失败
- Given 我提出的问题超出排障能力（如开发咨询、提单、链路拓扑查询、闲聊）
- When 意图识别判定为「超能力意图」
- Then 系统返回引导式回应（明示「这是 X 类问题，请走 Y 渠道」），不调用底座、不猜测、不真实转发
- Given 意图识别置信度低，或我对分类结果不满意（如被误判为资源查询）
- When Agent 追问澄清 / 给出候选意图选项，或我主动纠正（如「我要的是排查，不是查数」）
- Then 系统按纠正后的意图重新路由执行，会话保留误分类与纠正记录，无需我重新完整提问
- Given logquery 返回空结果
- When 报告组装
- Then 报告明示「时间窗内无匹配日志」并列出已尝试的查询条件与时间窗，不编造结论

## Story 3: 资深运维 / SRE 深度排障并回溯历史诊断

**As a** 资深运维 / SRE
**I want to** 查看诊断报告的每一个结论对应的数据源引用，并回溯历史诊断记录
**So that** 我能二次核实诊断可信度，并对重复出现的故障复用既有结论。

**Acceptance Criteria:**
- Given 一份诊断报告生成
- When 我点击某个结论
- Then 该结论能回指具体数据源（日志 / 指标 / 资产记录）
- Given 任一排障会话已结束
- When 我按租户 / 时间 / 服务名检索
- Then 我在 1 分钟内检索到该会话的完整内容（提问、编排调用链、报告、引用），且不跨租户可见

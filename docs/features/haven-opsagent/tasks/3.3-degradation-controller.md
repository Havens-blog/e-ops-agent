# 3.3: DegradationController 三级降级

## Description
实现三级降级统一决策器：L0 正常 / L1 模板意图匹配（规则结论 + 预置报告模板填充）/ L2 预置查询入口（`settings.preset_queries` 目录，点击后确定性重入流水线）/ L3 明示降级（告知降级模式 + 可用能力边界，绝不编造）。逐级尝试、只降不升，会话冷却 5min 内不再探活，冷却后探活成功即回升。

## Acceptance Criteria

- [ ] L1：LLM 不可用时意图走模板匹配，报告由预置模板填充规则结论（`degradeLevel=1, degraded=true`）
- [ ] L2：模板匹配置信度 <0.6 或抽取不出服务名 → 返回预置查询目录（`type=preset_entries, presets`）
- [ ] L3：预置目录空或规则结论不可得 → 明示降级说明（`type=degraded_notice`），绝不编造内容
- [ ] 只降不升 + 冷却/回升策略生效
- [ ] 降级状态计入 `TraceStep.DegradeLevel`，随响应返回前端徽标
- [ ] 单元测试覆盖 L0→L3 全路径 + 冷却回升（≥80%）

## User Stories
- Story 1/2：LLM 不可用三级降级（模板匹配/预置入口/明示降级）

## Hard Rules
- 绝不返回看似正常的编造内容
- 降级触发/恢复均落监控

## Implementation Notes
- L2 预置查询重入路径不调用 LLM（确定性）
- 三级 type 枚举与 api-handbook §1 严格一致

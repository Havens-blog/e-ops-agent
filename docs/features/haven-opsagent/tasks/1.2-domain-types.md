# 1.2: 领域类型与共享枚举/结构

## Description
实现 tech-design「Shared Types」全部类型（`Severity/RiskLevel/IntentType` 枚举；`Timeframe/DiagnoseParams/IntentCandidate/LogEntry/AssetRecord/Identity/Notification/NotifyResult/AlertEvent/LLMMessage/LLMRequest/StatusChange/TraceStep/SessionSummary/PresetQuery/Datasource/LLMProviderConfig/NotifyChannel/RiskWhitelistEntry`）+ 编排产物结构（`Diagnosis/RiskEntry/Conclusion/Citation/DispositionStep/Session`），并定义 5 个核心接口签名（`IntentClassifier/BaseModuleClient/Orchestrator/LLMProvider/RiskRegistry`）。

## Reference Files
- docs/features/haven-opsagent/design/tech-design.md — Interfaces、Shared Types（跨接口共享类型，唯一定义处）
- docs/features/haven-opsagent/design/api-handbook.md — Data Contracts（API DTO 与本节 json tag 必须一致）
- docs/features/haven-opsagent/design/er-diagram.md — sessions 实体字段（Session 结构来源）

## Acceptance Criteria

- [ ] 全部 Shared Types 以 Go struct 定义，json tag 与 api-handbook Data Contracts 逐字段一致（唯一权威定义）
- [ ] 5 个接口签名按 tech-design Interfaces 定义，方法签名含完整类型（无未定义类型引用）
- [ ] 枚举（Severity/IntentType/RiskLevel/状态）带合法性校验函数
- [ ] `Fingerprint = sha256(tenant + serviceName + metric + level)` 取前 32 位十六进制，含单元测试
- [ ] `Session` 结构补齐（`RunChat` 参数），字段覆盖 er-diagram `sessions` 集合

## User Stories
支撑全部用户故事（类型为跨模块 Ground Truth）。

## Hard Rules
- Shared Types 是唯一权威定义处，后续任务不得复制重定义
- json tag 与 api-handbook 一致（前端 TS 类型据此生成）

## Implementation Notes
- 落地到 `internal/domain/`（类型 + 枚举校验）
- 指纹函数放 `internal/domain/fingerprint.go`，供 worker 去重与告警记账复用

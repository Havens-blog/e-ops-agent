# 2.3: repository/dao 告警记账/预算/配置/补偿

## Description
实现 `alerts` / `llm_usage` / `settings` / `compensations` 四个集合的 Mongo DAO：告警按指纹窗口记账（首条建文档 + 后续同指纹 `$inc count` 置 `merged`）、LLM 滚动 1h 预算账本、系统配置读写（含 preset_queries / guided_templates）、落库补偿队列（写入 + 重试扫描）。

## Reference Files
- docs/features/haven-opsagent/design/tech-design.md — Data Models（alerts/llm_usage/settings/compensations）、Error Handling Propagation（compensations 属主）
- docs/features/haven-opsagent/design/er-diagram.md — 四实体字段
- docs/features/haven-opsagent/design/api-handbook.md — §8 settings 契约、§9 告警 webhook 记账规则

## Acceptance Criteria

- [ ] alerts 按 `(tenant_id, fingerprint, window_start)` 记账：首条 `new,count=1`，同指纹后续 `$inc count` 置 `merged`；溢出丢弃写 `overflow_dropped` 保留 raw_payload
- [ ] llm_usage 按 `(tenant_id, window_start)` 聚合 calls，可判预算耗尽
- [ ] settings 按 scope 读写，`tenant_id=""` 为全局哨兵；preset_queries/guided_templates/risk_whitelist/notify/llm/datasource 六类
- [ ] compensations 写入失败项（含 payload/retry_count），`status: retry|dead` 供重试扫描
- [ ] 单元测试覆盖记账/预算/配置读写（≥80% 覆盖）

## User Stories
- Story 1：告警去重记账、LLM 预算降级、队列溢出保留原文
- 系统配置（settings）支撑 Page Map 系统配置页

## Hard Rules
- 所有读写带 tenant 谓词（settings 全局哨兵除外）
- Redis 仅作去重/预算触发信号，补偿项存储以 Mongo 为准

## Implementation Notes
- 重试循环属主为 `internal/worker`（4.2 任务），本任务只提供读写 DAO

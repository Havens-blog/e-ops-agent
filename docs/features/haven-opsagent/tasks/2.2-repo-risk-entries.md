# 2.2: repository/dao 风险中心条目 CAS 状态机

## Description
实现 `risk_entries` 集合的 DAO + CAS（compare-and-swap）乐观锁状态机：`pending_view → viewed → done`。更新统一走 `findAndModify` 过滤 `{_id, tenant_id, version}`，成功后 `$inc version` 并追加 `status_history`；version 不匹配返回冲突交给 service 层映射 409。含『列表内展开/详情页』触发的窄状态迁移（`pending_view → viewed` 惰性 CAS）。

- docs/features/haven-opsagent/design/tech-design.md — Data Models（risk_entries：version CAS 乐观锁）、Error Handling（ERR_CONFLICT 409）
- docs/features/haven-opsagent/design/er-diagram.md — risk_entries 实体（version 字段 + status_history）
- docs/features/haven-opsagent/design/api-handbook.md — §3/§4/§5/§6 单条/批量 CAS + 自动已读语义

## Acceptance Criteria

- [ ] 状态合法流转（`pending_view → viewed → done`）经 CAS findAndModify 更新，version 每次 `$inc`
- [ ] 单条标记成功后返回含自增 version 的最新条目
- [ ] 并发冲突（version 不匹配）返回「冲突 + 最新条目」，供上层映射 409
- [ ] 批量逐条 CAS，成功/失败分别聚合，冲突不覆盖并发单标
- [ ] 自动已读触发（`GET /diagnosis/:id?riskEntryId=` 惰性 `{_id, tenant_id, status:"pending_view"} → viewed`）幂等
- [ ] 单元测试覆盖状态机全流转 + 并发冲突场景（≥80% 覆盖）

## User Stories
- Story 1：风险中心查看/标记已处理、批量标记、并发冲突提示
- Story 2/3：诊断详情查看自动流转已查看

## Hard Rules
- 状态仅记录值班处理进度，不触发任何写操作
- CAS 过滤必须含 `tenant_id`（跨租户 404 不泄露存在性）

## Implementation Notes
- `version` 初始 1，每次更新 `$inc`（api-handbook expectedVersion 取值来源）

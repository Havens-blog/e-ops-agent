# 4.5: web 风险中心 handler（list + 单/批量 CAS + stats）

## Description
实现风险中心 HTTP handler：`GET /opsagent/risk-center`（按租户/时间/服务名/状态/severity 筛选 + 分页 + stats 聚合）、`POST /opsagent/risk-center/:id/status`（单条 CAS）、`POST /opsagent/risk-center/batch-status`（批量逐条 CAS，`items[{id, expectedVersion}]`，冲突进 failed 清单）。响应含 `stats{pendingView, todayNew, highRisk}`。

## Reference Files
- docs/features/haven-opsagent/design/api-handbook.md — §3 风险中心列表、§4 单条标记、§5 批量标记（逐条 CAS）
- docs/features/haven-opsagent/design/tech-design.md — Data Models（risk_entries 状态机）、Error Handling（ERR_CONFLICT 409）
- docs/features/haven-opsagent/design/page-map.md — 风险中心页数据源

## Acceptance Criteria

- [ ] 列表按租户/时间/服务名/状态筛选，跨租户不可见（SC-6）
- [ ] 列表响应含 stats 聚合（pendingView/todayNew/highRisk）
- [ ] 单条标记 CAS 成功返回自增 version；冲突返回 409 + 最新条目
- [ ] 批量逐条 CAS，成功/失败分别聚合，失败清单含 reasonCode + currentVersion（供重试）
- [ ] 高危条目（riskLevel=high）数据不包含确认/执行字段
- [ ] 集成测试覆盖筛选/单标/批标冲突（≥80%）

## User Stories
- Story 1：风险中心筛选、单条/批量标记、部分失败回显 + 重试、并发冲突

## Hard Rules
- 批量不做整批事务，逐条 CAS，不覆盖并发单标
- 状态标记不触发任何写操作

## Implementation Notes
- stats 聚合走 Mongo aggregation pipeline
- 批量上限 50（可配），单次 logquery 截断 1000/10MB 不在此任务

# 4.2: 补偿重试循环（compensations worker）

## Description
实现 `internal/worker` 内的落库补偿重试循环（与告警 worker 隔离的 goroutine）：每 30s 扫描 `compensations`（status=retry 且 next_retry_at ≤ now）逐条重放，成功删除、重试达上限 5 次标记 `dead` 并推运维告警。该循环是 `compensations` 集合唯一读写属主。

- docs/features/haven-opsagent/design/tech-design.md — Error Handling Propagation（compensations 属主 + 重试上限 5 次 + dead 告警）
- docs/features/haven-opsagent/design/er-diagram.md — compensations 实体

## Acceptance Criteria

- [ ] 每 30s 扫描 `idx_comp_retry`（status=retry 且 next_retry_at ≤ now）
- [ ] 逐条重放成功即删除；达上限 5 次标记 `dead`
- [ ] `dead` 触发运维告警
- [ ] 重放幂等（不产生重复 session 文档）——补偿项带幂等键
- [ ] 单元测试覆盖重放成功/dead/幂等（≥80%）

## User Stories
- Story 1：落库失败补偿重试（结果最终可回溯）

## Hard Rules
- compensations 集合唯一读写属主是本 worker，落库失败方只写入
- 重放必须幂等

## Implementation Notes
- 幂等键为 session/diagnosis 业务唯一 ID
- 与 4.1 告警 worker 同进程池但互相隔离

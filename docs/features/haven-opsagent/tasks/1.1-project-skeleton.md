# 1.1: opsagent 服务骨架与模块装配

## Description
在 `D:\Haven` 下新建独立编排层服务 `opsagent`（Go）：`go.mod`（module `github.com/Havens-blog/opsagent`）、`cmd/opsagent/main.go`、`internal/` 分层目录（web/orchestrator/llm/risk/worker/baseclient/notify/repository/domain/config/middleware）、配置加载（数据源/LLM/通知/阈值/白名单，YAML + env 注入）、gin + gotomicro/ego 装配、eiam 鉴权中间件接入。复用 e-cam-service 的装配模式（`internal/<mod>/{domain,repository/dao,service,web,module.go}`）。

## Reference Files
- docs/features/haven-opsagent/design/tech-design.md — Overview、Architecture、Dependencies（模块装配模式与单实例约束）
- docs/features/haven-opsagent/design/api-handbook.md — 响应信封与路由前缀约定
- D:\Haven\e-cam-service\internal\alert\module.go — InitModule + RegisterRoutes 先例
- D:\Haven\e-cam-service\go.mod — gin/ego/mongox/redis 依赖清单

## Acceptance Criteria

- [ ] `go build ./...` 通过，`go run ./cmd/opsagent` 可启动并监听配置端口
- [ ] 配置从 YAML + env 加载（LLM/通知/阈值/白名单），缺失必需项启动即失败并报明确错误
- [ ] eiam 鉴权中间件接入：未登录/无效令牌返回 401（`ERR_TENANT_DENIED`）
- [ ] tenant 由服务端从 eiam 会话强制注入请求上下文（客户端传值丢弃）
- [ ] 目录结构遵循 `internal/<mod>/` 分层，与 e-cam-service 装配模式一致

## User Stories
支撑全部用户故事（基础设施）。

## Hard Rules
- 仅新建 `D:\Haven\opsagent\` 目录，不改写 e-cam-service 既有模块
- 复用的 gin/ego/mongox/redis 依赖须在 e-cam-service/go.mod 中已存在，P1 不新增第三方库

## Implementation Notes
- 目标仓库为 `D:\Haven`（独立 git 仓库，master 分支），非当前 docs 仓库
- `internal/config` 加载 `config/*.yaml`，env 覆盖敏感项（`OPSAGENT_ALERT_WEBHOOK_KEY` 等）
- `internal/middleware` 预留 `RequireTenant` + prompt injection 清洗挂载点（后续任务实现）

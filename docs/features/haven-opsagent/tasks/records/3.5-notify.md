### Key Decisions
- notify 为独立无状态层，依赖倒置注入 Sender（单次发送）+ Metrics（成功率埋点）两个窄接口，不 import baseclient 具体实现——传输复用 2.6 冻结的「opsagent 直连渠道 webhook」结论（B4），生产经组合根把直连 webhook 适配进 Sender，测试用 fake 免网络
- 重试上限 3 与 NotifyResult 塑造落在 Notifier（单点职责），语义与 domain.BaseModuleClient.Notify 一致：发送失败不返回 error、仅计入 NotifyResult.OK=false，不阻断风险中心落库与展示（Hard Rule）
- 埋点计数口径：成功只记 IncSuccess 一次（含重试后成功），终失败只记 IncFailure 一次（不在每次重试内累加），避免成功率分母被重试次数污染
- buildBody 四渠道形状差异显式化：钉钉/企微 markdown、飞书 text、邮件 subject/body（body.go switch 分支），并统一只携带标题+摘要+入口链接三条字段，杜绝跨租户明细混入
- metrics 为 nil 时埋点禁用、sender 为 nil 时快速终失败（含防御性失败返回），均不 panic——降级/单测场景安全

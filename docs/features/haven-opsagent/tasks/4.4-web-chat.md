# 4.4: web 对话排障 handler（chat + correct）

## Description
实现对话排障 HTTP handler：`POST /opsagent/chat`（创建会话 + 首轮提问同步编排，响应含 diagnosis/report/type/degradeLevel/presets/clarify candidates；超预算走 202 异步回退）+ `POST /opsagent/chat/:sessionId/correct`（一键纠正/自然语言纠正重路由）。响应与 api-handbook §1/§2 严格一致。

## Reference Files
- docs/features/haven-opsagent/design/api-handbook.md — §1 对话排障、§2 纠正端点（type 判别/202 异步/降级字段）
- docs/features/haven-opsagent/design/tech-design.md — 同步编排延迟预算（≤25s + http.Server 30s）、澄清与纠正落点
- docs/features/haven-opsagent/design/page-map.md — 对话排障页数据源

## Acceptance Criteria

- [ ] chat 成功返回 diagnosis + report（含数据源引用），1 分钟内端到端
- [ ] 降级响应 type 判别正确（report/preset_entries/degraded_notice/guided/clarify）
- [ ] 澄清：`NeedsClarify` 返回 type=clarify + candidates；纠正端点重路由并保留 correction_log
- [ ] 超编排预算（>25s）返回 202 异步（轮询 `GET /history?sessionId`）
- [ ] 落库失败返回 code=`ERR_PERSIST_FAILED`（HTTP 200）且 data.report 仍返回正文
- [ ] 集成测试（httptest）覆盖 chat 成功/降级/澄清/纠正/202（≥80%）

## User Stories
- Story 2：对话框自然语言排障、超能力引导、低置信度澄清纠正

## Hard Rules
- 超能力意图返回引导式回应，不调用底座
- 跨租户 session 纠正返回 404

## Implementation Notes
- 延迟预算逐阶段：意图 2s / 日志 8s·资产 5s 并行 / LLM 12s / 组装落库 3s
- 服务端 `http.Server` 写超时 30s

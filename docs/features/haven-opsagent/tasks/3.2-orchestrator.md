# 3.2: 编排流水线 Orchestrator + 4 逻辑 Agent 角色

## Description
实现 `internal/orchestrator`：`RunChat` 与 `RunAlert` 两条入口，编排流水线按意图生成步骤 → 4 个逻辑 Agent 角色（Coordinator 意图路由 / LogAnalyst 日志+资产 / Monitor 告警+指标 / Inspector 变更+拓扑 P1 stub）协作拉取证据 → 组装 `Diagnosis`（根因/结论/引用/处置预案/评分）→ 落库。每步记录 `TraceStep`（agent/action/耗时/降级级别），无数据步骤显式标注「未取得数据」。

## Acceptance Criteria

- [ ] `RunChat` 端到端：意图 → 编排 → 诊断 → 落库，返回含根因 + 处置建议 + 数据源引用的报告
- [ ] `RunAlert`：去重（供 4.1 调用）→ 排查 → 诊断 → 落库 → 风险条目 + 通知
- [ ] 4 个逻辑 Agent 角色独立实现、各自记录 TraceStep（agent/action/耗时）
- [ ] 单步失败/超时降级为「无数据」证据，报告显式标注并继续
- [ ] logquery 空结果 → 报告明示「时间窗内无匹配日志」+ 已尝试条件，不编造结论
- [ ] 组装结果含数据源引用（citation 回指日志/指标/资产），无数据支撑的推测显式标注

## User Stories
- Story 1/2：对话式排障 1 分钟返回只读报告
- Story 3：结论可回指数据源、编排调用链回溯

## Hard Rules
- P1 只读：编排不执行任何写操作
- 报告结论各自回指数据源，无依据不编造

## Implementation Notes
- 同步编排延迟预算（tech-design §延迟预算）：意图 2s / 日志 8s·资产 5s 并行 / LLM 12s→预算合计 ≤25s（下游 3.3/3.4 协作）
- Inspector 为 P1 stub（留接口），拓扑/变更数据 P2 接入

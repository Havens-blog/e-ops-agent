# 2.1: repository/dao 会话与诊断写入

## Description
实现 `sessions` / `diagnoses` / `citations` 三个集合的 Mongo DAO：写入路径（会话创建、诊断落库、引用落库）、按租户 + 时间/服务名检索（历史回溯）、按 `session_id` 关联查询。所有查询强制 tenant 谓词。

## Reference Files
- docs/features/haven-opsagent/design/tech-design.md — Data Models（sessions/diagnoses/citations）、Cross-Layer Data Map
- docs/features/haven-opsagent/design/er-diagram.md — 三实体字段与索引
- docs/features/haven-opsagent/design/schema.mongo.js — idx_sessions_tenant_time/service、idx_dx_session、idx_cit_dx

## Acceptance Criteria

- [ ] 会话 / 诊断 / 引用写入正确落库（含 `orchestration_trace`、`status`、`created_at`）
- [ ] 按 `(tenant_id, created_at)` 与 `(tenant_id, service_name)` 检索历史会话正确（SC-5）
- [ ] 所有 DAO 方法带 tenant 谓词，跨租户查询返回空（SC-6）
- [ ] 诊断 → 引用按 `diagnosis_id` 关联查询正确
- [ ] 单元测试经 CI Mongo 服务容器（`mongo:7` + `MONGO_URI` 注入，复用 `pkg/mongox`）通过，覆盖 CRUD + 租户过滤

## User Stories
- Story 3：资深运维回溯历史诊断、结论回指数据源
- Story 1/2：对话与告警诊断结果落库

## Hard Rules
- 不引入 testcontainers（go.mod 无此依赖）
- 所有查询强制 tenant 过滤

- 落库失败路径：暂不实现（补偿由 4.2 任务处理）；本任务关注正常写入 + 检索

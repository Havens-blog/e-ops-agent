# 2.5: RiskRegistry 风险分级确定性代码

## Description
实现 `internal/risk`：工具元数据注册表（`ToolMeta{Name, RiskLevel, Allowlist}`，静态声明只读/低危/高危）+ 白名单匹配。`Classify(tool)` 查表判定，工具未注册即返回错误；LLM 输出不得改变档位、不得引入未注册工具（P1 纯只读）。

## Reference Files
- docs/features/haven-opsagent/design/tech-design.md — Interface 5 RiskRegistry、Security Mitigations（风险分级确定性代码）
- docs/features/haven-opsagent/design/api-handbook.md — RiskWhitelistEntry（tool 必须命中注册表）

## Acceptance Criteria

- [ ] 注册表静态声明全部工具的风险档（read/low/high），`Classify` 查表判定
- [ ] 未注册工具返回错误（不默认放行）
- [ ] 白名单匹配生效，且 `RiskLevel=high` 不允许入白名单
- [ ] 单元测试覆盖查表命中/未命中/白名单/高危拒绝

## User Stories
- Story 1：高危条目不暴露确认控件（风险档判定来源）
- 支撑 P3 可控执行（预留）

## Hard Rules
- 风险分级由确定性代码完成，LLM 输出不得改变任何工具档位
- 白名单项必须命中注册表，未注册工具拒绝保存（400）

## Implementation Notes
- 注册表本体为 Go 代码（非 DB 表）；`settings` 仅承载白名单运维覆盖
- P1 只读：不渲染任何确认/执行控件
